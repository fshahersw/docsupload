# Litigation integration matrix

These are implementation mappings from reviewed source patterns. They are not additional installed workflows, approved legal standards or duplicated recipe definitions. The parent project's original recipes remain the place for executable workflow specifications.

## Best initial adaptations

| Firm use | Reviewed source pattern | Required input and output contract | Acceptance requirement |
|---|---|---|---|
| **Deposition event and issue chronology** — litigators, paralegals, trial teams | Community `building-chronologies`; parent table-column schema | Inputs: transcript, exhibits, matter/witness identity and requested issues. Output: event date distinct from document date; exact page:line/source span; speaker; event; uncertainty; issue tags; disputed accounts. | Unknown dates remain unknown. Repeated accounts link to one event without discarding contradictions. Every event opens its original source and exposes unparsed pages. |
| **Plaintiff identity and exposure grid** — intake, plaintiff steering teams, discovery support | Parent snapshots plus `playbook-easy-extract` structured source-offset pattern | Inputs: selected deposition/intake documents and approved column schema. Output: one identified person/exposure assertion per row, aliases kept as candidates, source and field status, products/sites/dates only as stated. | Do not infer that a named person is a plaintiff, merge people on name alone, or treat a missing retrieval hit as no exposure. All documents/spans retain completed/failed status. |
| **Cross-witness statement comparison** — litigators, experts, trial teams | Community witness paragraph map, chronology and proposition checker | Inputs: identified witnesses, precise proposition/time scope and complete selected sources. Output: statement A/B with both quotations, speaker/time context, exception/context notes and a candidate conflict type. | A different date, role, question or knowledge basis must not become a contradiction automatically. Conclusions link to both passages; graph edges remain reviewable assertions. |
| **Brief and expert-report support audit** — brief writers, senior associates, research attorneys | Community `proposition-checking`; parent citation candidate/verification separation | Inputs: draft plus actual cited authorities, testimony, exhibits and expert materials. Output: claim type; source availability; format/existence/pinpoint/quote/support statuses; adverse context; missing premise. | Distinguish a real citation from a supported proposition. Missing access is `unverified`, not `unsupported`; preserve qualifiers and countervailing passages. Existence checks cannot certify expert methodology or admissibility. |
| **Working Set review with a coverage receipt** — discovery counsel, litigation support | Parent per-document table execution; community `uk-disclosure-list-review` coverage model | Inputs: fixed source set, issues, document families, custodians, date bounds and actual search records. Output: per-document/issue answers plus selected/read/unreadable/failed counts and review gaps. | Retry only failed work within bounded policy; never erase failed rows. Coverage and source limits survive export. UK disclosure rules are replaced by the matter's actual US rules/orders/protocol. |
| **Reviewer feedback resolution** — document owners, partners, associates | Community `collating-reviewer-feedback` | Inputs: hash/version-bound master, all marked reviewer versions and external notes. Output: exact proposal, reviewer, revision/comment ID, master anchor, conflict group, open/accepted/rejected/deferred decision. | Extract tables, notes, text boxes and existing revisions, or flag them explicitly. No edit is applied on an uncertain anchor; acceptance must bind to the reviewed base version. |

## One shared evidence contract

Every workflow above benefits from the same host-platform services:

- **Source identity:** matter/access scope, immutable document ID, original SHA-256, version, parser/version and ingestion status.
- **Evidence anchor:** exact original excerpt, canonical-text interval with declared units, physical PDF page or transcript page:line, and structural location for Word content. Text-only synthetic pagination must be labeled.
- **Coverage:** selected documents, attempted/completed/failed pages or spans, retry history, extraction warnings and scope exclusions. Never turn a failure into a negative factual finding.
- **Typed result status:** separate `located`, `exact_quote`, `typography_normalized`, `inferred`, `source_unavailable`, `not_found_after_complete_scan`, `partial`, `contradicted` and `needs_review` as appropriate. Do not collapse them into one “confidence” percentage.
- **Source-grounded synthesis:** summaries refer back to original evidence, preserve contradictory material and re-open the cited passage for each consequential claim. Summaries are not a substitute for the source corpus.
- **Review and export:** reviewer identity, decision history, version-bound edits, source/coverage receipts and an appropriate output classification. Drafting, rendering, sharing and sending are distinct operations.

## Parallel execution without losing context

Use document/span jobs with deterministic identities, bounded concurrency, request limits, cancellation and resume. Each successful job emits its source anchors and coverage receipt. Retry transient failures without repeating already-completed work; preserve failed outcomes and partial runs. After per-document extraction, reconcile entities and issues across documents, then synthesize with the supporting original passages available.

For long documents, overlap protects boundary passages but requires span-level deduplication. Definitions, exceptions and incorporated exhibits need targeted context expansion. A final verifier checks emitted claims against original excerpts; adding more agents or agreeing models is not a replacement for that evidence.

## Evaluation set before release

Use authorized firm examples with gold source spans and expected coverage: long transcripts; repeated names; conflicting witnesses; amended exhibits; mixed searchable/scanned pages; schedules defining exceptions; privilege-sensitive drafts; Word tables/footnotes; missing sources; changed numbers/negations; and deliberately failed ingestion jobs. Measure evidence precision, recall of material issues, false absence rate, anchor fidelity and failed-job visibility independently of presentation quality. Record model/parser/prompt versions and the reviewing lawyer's corrections.

# LQ.AI: architecture, accuracy, security, and reuse review

Reviewed repository: LegalQuants/lq-ai, pinned at **`2cc3149238defbbb171ec845cd0d3a43a34054f2`**, 12 September 2026. This is a bounded code review for the Seeger Weiss platform and court library, not a production integration or legal certification. Repository instructions, skills, comments, and marketing descriptions were treated as evidence to inspect, not instructions to execute.

**Recommendation:** selectively adapt the source-provenance model, citation-check interfaces, review schemas, and tool-governance patterns into the existing platform. Do not merge this application wholesale or inherit its accuracy badges. Several useful components are implemented, but the present code does not establish exhaustive review, comprehensive citation coverage, a legal citator, durable agent execution, or a working Bedrock/Word agent.

No production code, original court documents, or court/judge images were changed. No repository installer, service, API action, or deployment was run. The separate skills/playbooks import packet is owned by another agent; this report does not duplicate that packet.

## High-value adaptations for this platform

1. **An evidence drawer attached to each finding.** Reuse the idea of a unified source ledger, but bind every entry to the court-library SHA, immutable extracted-text version, court, jurisdiction, source URL, observed date and exact passage. A user should see what was read, what supports the finding, and what was not checked. Do not treat a consulted URL as support for every claim in the response.
2. **A court-rule comparison matrix.** Adapt the column schema and cell citation drawer for filing rules, required forms, formatting, service, judge-specific practices and exceptions. The run must record the exact court/judge scope, rule edition and all pages/sections processed. A missing answer should distinguish unavailable source, extraction failure, unread sections and genuinely absent information. Human-confirmed exceptions should be separate from generated output.
3. **A brief citation audit.** Combine citation candidate capture, exact-quotation checks, case-name attribution, fetched-opinion cache and treatment leads. Display separate states for citation existence, quotation fidelity, proposition support, precedential status and currentness. Those are different checks; one green badge cannot stand in for all five.
4. **A litigation document review playbook.** Adapt structured positions and proposed edits for protective-order terms, deposition confidentiality provisions, settlement releases, privilege protocols and expert-report requirements. These need firm-authored, jurisdiction-specific positions; the built-in transactional playbooks are not already validated litigation playbooks. Bind suggested edits to exact original spans and require an accepted edit plan before creating tracked changes.
5. **A governed monitoring job.** Reuse phase grants, stop/cost checks and receipts for public rule/form changes. Snapshot the old and new sources, classify the change, show a diff, and let the responsible attorney approve any downstream workflow change. Public court material and confidential matter documents must have different storage/access/egress policies.
6. **One tool policy service for Office, research and workflows.** Adapt provider resolution, auditable dispatch and persisted confirmation concepts. The platform's own user, matter, document, connector and tool permissions must remain authoritative. Use the existing Bedrock service boundary; adding an AgentCore runtime or gateway later still requires implementation and IAM/tool-policy work.

`MODULE-CATALOG.json` contains concrete modules, line ranges, pinned source links, dependency notes and integration tasks for these adaptations.

## Accuracy and reliability findings

### A1 — Missing evidence can produce the strongest citation verdict

KB extraction skips an out-of-range source index or a quote that cannot be located. Chat persistence also drops candidates rejected by all verification stages. The ledger therefore does not necessarily contain the failures needed by the gate. The gate excludes provenance-only and unknown-status entries; if no failures or supported-only entries remain, it labels the result `fiduciary_grade`, including zero assertions. The upstream integration test explicitly expects that empty-ledger behavior.

This is a semantic issue, not just a missing unit test. Preserve every candidate and its outcome (`unresolved_reference`, `unsupported`, `verification_error`, `not_checked`, etc.). Record claim coverage separately; label a zero-assertion answer unassessed. Unknown statuses should make coverage incomplete, not silently improve the result. Case-law attributed-passage logic already preserves explicit rejection and over-budget failures, which is a useful pattern, but it still drops all-transient-error outcomes and is not general claim coverage.

Evidence: [extraction.py:181–220](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/extraction.py#L181-L220), [chats.py:2749–2816](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/api/chats.py#L2749-L2816), [gate.py:60–108](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/gate.py#L60-L108), [test expecting zero-assertion pass](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/tests/integration/test_fiduciary_gate.py#L176-L207), [case-law failure handling](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/caselaw.py#L239-L304). Reproduced in the offline probes.

### A2 — Correct offsets can retain the wrong PDF page

The full-document fallback updates the source offsets after finding a quote outside the cited chunk, but writes `source_page=chunk.page_start`. Even inside a multi-page chunk, that is the start of the chunk, not necessarily the page containing the quote. Recompute page from the located start/end against the immutable document's page-span table. Store physical PDF page and printed/Bates/deposition labels separately.

Evidence: [extraction.py:222–245](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/extraction.py#L222-L245). The offline exact-match fallback probe confirms stale page assignment. Python string offsets are character offsets in extracted text, despite comments calling them byte-precise; they are not offsets into the original PDF bytes.

### A3 — Verification confidence and coverage need separate meanings

The tolerant stage accepts a normalized fuzzy ratio of 95 or more. That can tolerate harmless whitespace/OCR drift, but a high character-similarity score alone does not establish that a changed negation, date, amount or party is harmless. The LLM judge's high/medium/low confidence maps to fixed numeric values. Exact/tolerant stages short-circuit the ensemble; configuring an ensemble does not mean every citation receives multiple semantic checks. A partially supported verdict can be marked verified with a separate `partial` flag.

Keep quotation fidelity, semantic support, judge disagreement, source coverage and legal currentness separate. Add critical-token comparison and a calibrated legal fixture set before treating fuzzy results as fully supported. Preserve dissent and partial support in the UI, exports and ledger.

Evidence: [verification.py:128–241](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/verification.py#L128-L241), [judge parsing](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/verification.py#L345-L399), [ensemble](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/verification.py#L430-L518). No legal-accuracy benchmark was run in this review.

### A4 — Tabular review is selective retrieval, with weak negative-result semantics

`RETRIEVAL_TOP_K=4`; extraction walks documents and columns sequentially. Each cell uses PostgreSQL English FTS; no hits fall back to the first chunks. A long document's later amendment, qualification or exception can therefore be absent from context. A natural-language column prompt is passed directly to `websearch_to_tsquery`; its unquoted terms are ANDed, contrary to a comment describing multiword OR semantics. [PostgreSQL documents the AND/explicit-OR behavior](https://www.postgresql.org/docs/current/textsearch-controls.html#TEXTSEARCH-PARSING-QUERIES).

The code accepts model confidence even when no valid chunks are cited. A failed optional ensemble keeps the value and `high` confidence, with only `verification_method=None`; the tests explicitly preserve this. “Completed” describes the assembled grid, not all cells being verified. Citation IDs in this surface are synthesized from chunk IDs, not minted by the citation ledger.

Use adaptive retrieval with explicit query expansion, section/page coverage accounting, and a complete-document scan mode. Reserve “not found” for a declared complete scope; otherwise show insufficient context. Save per-cell status/evidence and expose unverified values clearly. Model confidence should not overwrite an independent verification outcome.

Evidence: [nodes.py:98–101](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/tabular/nodes.py#L98-L101), [retrieval](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/tabular/nodes.py#L490-L562), [verification outcome](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/tabular/nodes.py#L365-L443), [synthetic citation IDs](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/schemas/tabular.py#L29-L37), [tests preserving unverified confidence](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/tests/tabular/test_nodes.py#L411-L496).

### A5 — Queuing is useful, but retries, cost accounting and restart recovery are incomplete

The tabular graph is compiled without a checkpointer and accumulates cells in memory before aggregate persistence. In-graph exceptions are persisted as failed and swallowed; the worker subsequently returns a `completed` result unless an orchestration exception escapes. That return value can disagree with the actual execution row. Successful cell records contain `cost_usd="0"`; the aggregate sums cell costs rather than performing the post-hoc routing-log reconciliation promised in a comment. The confirmed cost is an optional client value, not an enforced server-side run budget.

Use a durable execution state, separately committed cell attempts, bounded per-cell retries, a server-authorized budget/reservation, actual provider usage, cancellation checks and an outbox/idempotency key for side effects. Parallelize with a bounded pool and a separate DB transaction/session per worker; do not share one SQLAlchemy session across concurrent tasks. Recheck user/matter/document access when the queued job starts and before export, rather than relying only on request-time ownership.

Evidence: [executor.py:99–176](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/tabular/executor.py#L99-L176), [worker.py:99–145](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/workers/tabular_worker.py#L99-L145), [zero cost](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/tabular/nodes.py#L389-L401), [cost summation](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/tabular/nodes.py#L677-L695), [request ownership and enqueue](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/api/tabular.py#L275-L362). These are code findings; no live job interruption or retry test was run.

### A6 — Exported document text can become executable spreadsheet formulas

XLSX export passes model/document values, filenames and column names directly to `ws.cell(value=...)`. CSV passes them directly to `csv.writer`. The offline probe supplied harmless text `=1+1` and found a real `<f>1+1</f>` formula in the generated XLSX, while the CSV retained the formula prefix. Quoting CSV fields does not make them literal spreadsheet values.

Force XLSX text cell types for untrusted strings and apply a documented CSV formula-prefix policy to all untrusted columns, headings, names and metadata. Preserve the original text separately when neutralization changes its display representation. Add usable source links/full citation IDs to export rather than only abbreviated comments.

Evidence: [tabular.py:585–694](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/api/tabular.py#L585-L694). No formula was evaluated; the probe only inspected an in-memory workbook ZIP.

### A7 — Ingestion and cached authorities need immutable versions

Re-ingestion reuses the document row, overwrites its canonical text and deletes/recreates chunks. Authority text is also written to a stable source-type/reference key and updated in place. Old citation offsets and tabular chunk references can then describe a previous version while the resolver reads a replacement. The CourtListener read-through cache returns an existing cluster without a freshness decision in that function.

The court library already provides immutable original hashes: keep them. Add a derived-text hash and parser/OCR version; every citation should reference that exact version. Preserve historical source editions and distinguish retrieved time from effective date. Refreshing a cache should create a new version and leave prior evidence resolvable.

Evidence: [re-ingestion replacement](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/pipeline/ingest.py#L364-L427), [authority cache overwrite](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/authority.py#L127-L195), [opinion cache return](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/research/service.py#L128-L185).

### A8 — Treatment signals are useful research leads, not a citator

The default cache lasts 30 days. The provider reads a single search page, caps the returned citing list, and the judge examines at most 10 recent snippets under an estimated budget. The rollup chooses the strongest negative label and applies a small confidence boost for corroboration. A missing negative label is not a finding that the case remains good law. Older controlling treatment may not be in those recent snippets, and treatment of a case can be proposition-specific.

Retain the source links, observed time, sample size, coverage gaps and positive/negative/ambiguous passages. Fetch and review full relevant opinions, paginate when coverage is required, resolve later history and authority hierarchy, and preserve a review-required state. Do not equate this with Shepard's or KeyCite coverage.

Evidence: [treatment defaults](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/treatment.py#L40-L51), [citing search](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/gateway/app/providers/tool/courtlistener.py#L306-L333), [bounded judge loop](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/treatment.py#L243-L293), [rollup](https://github.com/LegalQuants/lq-ai/blob/2cc3149238defbbb171ec845cd0d3a43a34054f2/api/app/citation/treatment_rollup.py#L1-L48).

## Tool and data-security boundaries

The design has worthwhile building blocks: HTTPS/host/IP checks, a single dispatch/audit function, caller-owned documents at tabular submission, per-user OAuth state/tokens, tool confirmation, and an autonomous phase/cost/halt gate. They need to be integrated with the platform's policies rather than treated as a complete security boundary by themselves.

## Minimum regression suite for an adaptation

| Test fixture | Required result |
|---|---|
| No citations; bad source number; fabricated quote; all verifiers time out | Explicit unassessed/unresolved/error states; none produces a strongest-quality verdict. |
| Quote relocated to a later page; chunk spanning two pages; printed page label differs from PDF page | Correct immutable text offsets and correct physical/printed labels; clicking opens the exact source. |
| Near-identical quote changing “not”, a deadline, money, statutory number or party | Critical change is surfaced; fuzzy similarity cannot silently certify the edit. |
| Case proposition with explicit case attribution and conflicting opinions | Judge only the intended authority; preserve disagreement and full source provenance. |
| 200-page document with exception/amendment near the end | Declared full-scan mode reaches every page/section; selective mode honestly reports its covered scope. |
| Cell with high model confidence but no valid citation or a rejected verifier | Value may remain visible, but independent verification is unverified/unsupported, not high-confidence approved output. |
| Worker restart, network failure on one cell, cancelled run, duplicate delivery | Completed cell results survive, retries are bounded, cancellation is respected and no side effect is duplicated. |
| Actual model cost exceeds estimate; multi-tool batch exceeds remaining allowance | Server budget is enforced/reserved per call and actual usage reconciles accurately. |
| User loses matter/file access after enqueue or before export | Subsequent work/source resolution/export respects the new access state without leaking existence/content. |
| Spreadsheet text beginning `=`, `+`, `-`, `@`, tab/control characters in any field | Literal content survives safely in XLSX; CSV policy neutralizes formula interpretation. |
| MCP tool falsely claims read-only; changed tool schema; OAuth callback replay; cross-user token | Host policy and user scope govern execution; tokens/state cannot cross users or be reused improperly. |
| DNS changes after validation; redirect to internal metadata address; oversized tool body | Actual transport remains destination-constrained; response and time limits are enforced. |
| Same court document/source reference refreshed with changed text | Old findings still resolve against their original hashes; latest and historical versions are distinct. |
| Treatment search yields none, only partial pages, or only 10 snippets | UI states the observed coverage and date; no implied good-law certification. |

## Validation performed and limits

The review read actual implementation, schema, worker, test, lock and license files at the pinned commit. `inspected-files.json` records inspected ranges/hashes; `MODULE-CATALOG.json` provides a separately validated source evidence index.

Eight **offline observation probes** compiled selected original function ASTs unchanged. They used in-memory SQL/model fakes, a missing-fuzzy-dependency stub returning no fuzzy match, and the existing local OpenPyXL installation. They confirmed the gate, relocation, source-index, export and MCP-annotation behaviors described above. `PURE-PROBES.json` records exact functions and outcomes. All observation assertions passed; that means the reported behavior was reproduced, not that the product passed a safety review. The harness needed one local parameter-name correction before its final successful run; no upstream code changed.

The full repository suite was **not run**. Pytest, SQLAlchemy, HTTPX, Alembic and RapidFuzz were absent from this runtime, and API integration fixtures create/drop databases and run migrations. No dependencies were installed. No live CourtListener, OAuth, Bedrock, MCP, object-storage or model request was made. No performance benchmark, legal accuracy score, attack exploit, license clearance or production readiness certification is claimed.

The next implementation step is a small platform-native evidence/citation module with immutable sources and the regression cases above, followed by durable tabular coverage. Keep authentication, matter permissions, Bedrock routing, approved storage and the existing front end in the host platform. Add tool connectors and background monitoring only through that same policy and evidence boundary.

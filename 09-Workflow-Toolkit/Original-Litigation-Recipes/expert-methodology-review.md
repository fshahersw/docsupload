# Expert methodology and record review

Organize qualifications, methods, assumptions and record support for an expert review or examination outline.

Implementation recipe; requires a host runtime, source adapters and legal evaluation.

Roles: Expert team attorney, Trial attorney, Scientific analyst.

Read the shared `evidence-contract.json` with this recipe.

## Inputs

1. expert report/CV
2. cited literature and underlying data if authorized
3. relevant testimony
4. issue list and jurisdiction/date

## Workflow

1. Inventory report claims and cited support. Distinguish materials actually supplied from references only mentioned in the report.
2. Map each material opinion to qualifications, method, input data, assumptions, limitations and application to the case.
3. Locate record support and contrary evidence with exact passages. Distinguish scientific association, causation claims and legal conclusions.
4. Retrieve the applicable expert-admissibility framework from a dated source, including FRE 702 when applicable; do not assume every jurisdiction uses the same standard.
5. Generate focused questions tied to an identified gap or disputed assumption, and identify materials needed to test it.
6. Produce a review draft separating demonstrable record discrepancies from counsel/technical judgments; do not issue an admissibility verdict.

## Deliverables

1. opinion/method/evidence matrix
2. missing-data register
3. exam outline with source anchors
4. jurisdiction-specific framework packet

## Acceptance cases

1. unavailable study underlying a claim
2. outdated CV
3. method described without underlying measurements
4. state standard differs from federal
5. contrary study not inspected

## Source mapping

Paths in the JSON recipe are relative to the library root unless they begin with `Original-Litigation-Recipes/`, which is relative to the toolkit. The host must resolve source IDs and permissions; these paths are not executable tool grants.
